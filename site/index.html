01

Conditions of deposit

Expiry
Until you stop it. --ttl 30m, 2h, or 1d if you want it to close itself.
Collections
--downloads 5 closes the share after the fifth. A visitor seeking inside a video does not spend one.
Key
128 bits from crypto/rand in every URL. --password adds one of yours, stored as an Argon2id digest.
Custody
Bytes are read from your disk as the visitor downloads. Nothing is copied to a server, because there is no server.
Scope
Visitors reach only what you named. A file share is that file, not the folder it sits in. ../ and escaping symlinks 404.
Withdrawal
vrok list shows what is open. vrok revoke a82kd9 kills one URL now.

Not just files

  • A single file

    Any type. Video gets a player with seeking, images a viewer, code gets highlighted, a PDF opens inline.

    vrok ./cut-03.mp4

  • A whole folder

    Browsable, with an index. A built site or a Playwright report behaves like the real thing.

    vrok ./playwright-report

  • Several at once

    One index page in front of all of them, so a client gets a single link instead of five.

    vrok report.pdf shot.png a.mp4

  • A running server

    Reverse-proxied, with WebSockets intact, so hot reload keeps working for whoever you sent it to.

    vrok localhost:3000

What the other person opens

The link is a page, not a raw file dump. They can view what the browser can show — video with seeking, images, PDFs, code, a folder listing — and download the original bytes. Nothing else on your machine is on that page.

  • View. Video, audio, images, PDF, HTML, Markdown, JSON, text, and zip listings render in the page.
  • Download. The original file, with Range support so a video can resume.
  • Browse. A folder share is a listing. Click a name to view it; the arrow downloads that file only.
  • Locked. A password share shows a locker form. Nothing about the file is visible until it unlocks.
  • All at once. A folder page has a Download all (.zip) button, built while it downloads.
  • Checked. The file page shows its SHA-256, so the other person can confirm their copy is intact.

Why this, and not the usual tools

Most tools either upload a copy of a file, or expose a port until you remember to turn them off. vrok creates a share: a temporary URL to something that is already on your machine.

The bytes stay put

A visitor’s request is read from your disk (or proxied to your localhost) while they wait. There is no cloud copy to revoke later, because none was made.

Only what you named

Sharing demo.pdf opens that file, not Documents, not ../, not a symlink that walks out. Everything else 404s the same way.

The URL is supposed to die

Until you stop it, or sooner if you set a TTL or a download cap. A forgotten ngrok tunnel and a WeTransfer link from last month are the opposite idea.

One binary, no account

No signup, no dashboard, no team plan. Install, run, send the link. Privacy and security details live in the guide.

Free and open source

MIT licensed. No paid tier, no usage meter. Read it, fork it, or open the source.

Use ngrok when you want a long-lived tunnel to a port you already serve. Use a file host when the recipient must still have the file after you leave. Use vrok when someone needs what is on your machine now, and should not have it tomorrow. Full usage and security guide.

Why vrok, not ngrok or WeTransfer

Upload services make you wait, then keep a copy. Tunnels stay open until you remember them. vrok gives someone a link to what is already on your machine, for exactly as long as you decide.

Share now, not after an upload

The link works the moment vrok starts, with a QR code under it for a phone to scan. They are already downloading while an upload service would still be uploading.

What the other person gets

  • Nothing to install. Any browser on any device. On a phone, they scan the QR code vrok prints and the link opens. No app, no account, no sign-in.
  • View. Video, audio, images, PDF, HTML, Markdown, JSON, text, and zip listings render in the page.
  • Download. The original file, with Range support so a video can resume.
  • Browse. A folder share is a listing. Click a name to view it; the arrow downloads that file only.
  • Locked. A password share shows a locker form. Nothing about the file is visible until it unlocks.
  • All at once. A folder page has a Download all (.zip) button, built while it downloads.
  • Checked. The file page shows its SHA-256, so the other person can confirm their copy is intact.

Safe by default

Expiry
Works until you stop it. --ttl 30m, 2h or 1d makes it close itself.
Download limit
--downloads 5 closes the share after the fifth. Seeking in a video or resuming a download does not use one up.
Password
--password, or press p while it runs. Stored as an Argon2id digest, never in plain text.
Nothing uploaded
Bytes are read from your disk as the visitor downloads. There is no server holding a copy, so there is nothing to delete later.
Only what you named
A file share is that file, not the folder it sits in. ../ and symlinks that point outside answer 404. Every URL carries 128 random bits.
Revoke
vrok list shows what is open. vrok revoke a82kd9 kills one URL now.

Questions people ask

How do I share a large file without uploading it?

Run vrok ./video.mp4. vrok serves the file from your own machine through a temporary public URL, so nothing is uploaded first and there is no size limit beyond your disk. The person you send the link to can watch it in the browser or download the original, and an interrupted download resumes.

How do I share my localhost with someone?

Run vrok localhost:3000 while your dev server is running. You get a public HTTPS URL that reverse-proxies to it, with WebSockets intact, so hot reload keeps working for the person you send it to. No account, no configuration.

Is vrok a free ngrok alternative?

For sharing, yes. vrok is free, open source (MIT) and needs no account. It exposes a localhost port like a tunnel does, and it also serves files and folders directly, with previews, download limits, passwords and an expiry. How it compares.

How is vrok different from WeTransfer or Google Drive?

Those services upload a copy of your file to their servers and keep it there. vrok uploads nothing: visitors read the file from your machine while the command runs, and the link stops working when you stop it or it expires.

Can I make a link that expires or works only once?

Yes. --ttl 2h closes the share after two hours, --downloads 1 makes it a one-time link, and --password asks visitors for a password. While a share runs, press 1, e or p to change these without changing the URL.

Can people see other files on my computer?

No. A visitor reaches only what you named: sharing one file exposes that file, not the folder around it. Paths like ../ and symlinks that point outside a shared folder answer 404. A public link is an unguessable hostname; a link on your own network still hides the share behind a 128-bit token.

Does the other person need to install anything?

No. They open the link in any browser, or scan the QR code vrok prints with a phone camera. Only the person sharing runs vrok.

Can someone send me files with vrok?

Yes. Run vrok receive and send them the link, or let them scan the QR code. They pick files on an upload page, you see the names and sizes in your terminal and press y, and the files land in ~/Downloads/vrok. Nothing is written before you accept, and a file already there is never replaced. Receiving files.

Does it work on Windows, macOS and Linux?

Yes. vrok is a single binary for macOS (Apple silicon and Intel), Linux (x86_64, ARM64, ARMv7), Windows and FreeBSD, installable with one command, Homebrew, Scoop, a Linux package (.deb, .rpm, .apk) or a verified archive.
